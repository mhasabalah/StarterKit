# Production Secrets

This directory contains **production secrets** for the StarterKit application.

## 🔐 Required Secret Files

The following files must exist for production deployment:

- `postgres_password.txt` - PostgreSQL database password
- `redis_password.txt` - Redis cache password
- `jwt_secret.txt` - JWT signing secret key
- `seq_admin_password.txt` - Seq admin password (generated by `deployment/secure-seq.sh`)

## ⚡ Quick Setup

Run the automated setup script:

```bash
./deployment/secrets-setup.sh
```

This will generate all required secrets with cryptographically secure random values.

## 🛠 Manual Setup

If you prefer to set secrets manually:

```bash
# PostgreSQL password (32+ chars recommended)
openssl rand -base64 24 > secrets/postgres_password.txt

# Redis password (32+ chars recommended)
openssl rand -base64 24 > secrets/redis_password.txt

# JWT secret (64+ chars recommended)
openssl rand -base64 48 > secrets/jwt_secret.txt

# Set secure permissions
chmod 600 secrets/*.txt
```

## 🔍 How Secrets Are Used

### Production (docker-compose.yml)

```yaml
secrets:
  postgres_password:
    file: ./secrets/postgres_password.txt
  redis_password:
    file: ./secrets/redis_password.txt
  jwt_secret:
    file: ./secrets/jwt_secret.txt

services:
  api:
    secrets:
      - postgres_password
      - redis_password
      - jwt_secret
```

Docker mounts these files at `/run/secrets/` inside containers.

### Development (docker-compose.override.yml)

Development uses direct environment variables from `.env` file:
- No secret files needed
- Simpler for local development
- Less secure (acceptable for dev)

## 🚨 Security Best Practices

### ✅ DO:
- Generate secrets using `openssl rand -base64`
- Use at least 24 bytes (32 base64 chars) for passwords
- Use at least 48 bytes (64 base64 chars) for JWT secret
- Set file permissions to `600` (owner read/write only)
- Backup secrets securely (encrypted)
- Rotate secrets periodically

### ❌ DON'T:
- Commit secrets to git (this directory is gitignored)
- Share secrets in screenshots/logs
- Use weak passwords (< 16 chars)
- Reuse secrets across environments
- Store secrets in plain text elsewhere

## 📋 Verification

Check that secrets are properly configured:

```bash
# List secret files
ls -lh secrets/*.txt

# Expected output:
# -rw------- 1 user user  32 Jan 30 12:00 postgres_password.txt
# -rw------- 1 user user  32 Jan 30 12:00 redis_password.txt
# -rw------- 1 user user  64 Jan 30 12:00 jwt_secret.txt

# Verify permissions are 600
stat -c '%a %n' secrets/*.txt

# Verify secret lengths
wc -c secrets/*.txt
```

## 🔄 Rotation

To rotate secrets:

1. Generate new secrets:
   ```bash
   ./deployment/secrets-setup.sh
   ```

2. Rebuild and redeploy:
   ```bash
   docker compose build api
   docker compose up -d
   ```

3. Securely delete old secrets backup

## 🆘 Troubleshooting

### "No such file" errors

```bash
# Ensure secrets exist
ls -lh secrets/*.txt

# If missing, run setup:
./deployment/secrets-setup.sh
```

### "Permission denied" errors

```bash
# Fix permissions
chmod 600 secrets/*.txt
```

### Secrets not loading

```bash
# Check API logs for entrypoint output
docker compose logs api | grep "🔐"

# Should see:
# 🔐 Reading Docker secrets...
#   ✅ Loaded postgres_password (32 chars)
#   ✅ Loaded redis_password (32 chars)
#   ✅ Loaded jwt_secret (64 chars)
```
