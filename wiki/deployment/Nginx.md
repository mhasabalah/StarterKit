# Configure Nginx ingress

Host Nginx terminates TLS, proxies the API and SignalR hub, limits requests and restricts operational dashboards.

## Goal

Install the repository's proxy configuration with correct upstreams, certificate paths, forwarded headers and administrative access rules.

## Prerequisites

Have a reachable API listener, host Nginx, DNS for `api.example.com` and certificate tooling. Use
`deployment/nginx/` for the host deployment; `infra/nginx/` holds container-oriented configuration artifacts.
No `nginx` service is declared in the current root Compose files, even though old Makefile targets refer to one.

## Steps

1. Review the configuration files and actual listener topology.

   ### Architecture

   ```mermaid
   flowchart TB
     accTitle: Host Nginx routing
     accDescr: The shipped host proxy uses one API upstream and separate locations for hubs and tools.
     C[Client] --> N[Host Nginx TLS]
     N --> A[API listener 5000]
     N --> H[SignalR hubs]
     N --> T[Restricted tools]
     H --> A
     class C external
     class N,T infrastructure
     class A,H api
   ```
   *Figure: The shipped host proxy uses one API upstream and separate locations for hubs and tools.*

   ### Configuration files

   | Source | Responsibility |
   |---|---|
   | `deployment/nginx/nginx.conf` | Workers/events, JSON log formats, gzip, limit zones, upstream, proxy defaults, TLS session settings, site includes |
   | `deployment/nginx/conf.d/app-production.conf` | HTTP challenge/redirect, active HTTPS site, API/auth/health/hub routes, protected tools, error responses |
   | `infra/nginx/Dockerfile`, `nginx.conf`, `conf.d/app.conf`, `app-dev.conf`, `app-test.conf` | Alternative container artifacts; not a root Compose deployment |

   The global config includes both `/etc/nginx/conf.d/*.conf` and `/etc/nginx/sites-enabled/*`; install the site
   once to avoid duplicate blocks. The host upstream excerpt is from `deployment/nginx/nginx.conf`:

   ```nginx
   upstream starterkit_api {
       least_conn;
       server localhost:5000 max_fails=3 fail_timeout=30s weight=1;
       keepalive 32;
       keepalive_timeout 60s;
       keepalive_requests 100;
   }
   ```

   Additional replicas require distinct reachable listeners and matching upstream entries. Base Compose fixes
   container name and host port; `API_REPLICAS` does not create a second listener. There is no shipped sticky-session
   configuration or active HTTP health-check scheduler in Nginx; failure counters are passive.

2. Bootstrap certificates before installing the active HTTPS site.

   ### SSL/TLS configuration

   Use a temporary HTTP-only host site for first issuance, then `sudo certbot --nginx -d api.example.com`.
   The shipped site immediately references `fullchain.pem`, `privkey.pem`, `chain.pem`, Certbot's SSL options and
   DH parameters under `/etc/letsencrypt/`; those files must exist before validation. For a local rehearsal,
   use self-signed certificate paths in a separate copy. Never commit private keys.

   TLS 1.2/1.3, session cache and disabled session tickets are configured globally. HTTPS enables OCSP stapling
   and HSTS for two years with subdomains/preload. Verify the actual certificate/response and renewal timer;
   deployment configuration is not a certificate-quality guarantee.

3. Configure security and request behavior.

   ### Security

   | Concern | Shipped behavior |
   |---|---|
   | Main API | `api_limit` 100 requests/s, burst 50, no delay; API cache bypass |
   | Auth regex | `/api/(auth\|login\|register\|token\|refresh)`, `auth_limit` 10/s, burst 5 |
   | General zone | 50/s; Swagger/Scalar apply burst 20 |
   | Connections | `conn_limit` 20 per address; hub location has its own 50 budget |
   | Health | Exact `/health` and `/alive`, no access log or request limit, short proxy timeouts |
   | Tool ingress | Swagger/Scalar allow loopback then deny; Seq/Grafana/Prometheus/Jaeger deny all until edited |
   | Errors generated by proxy | 429 JSON plus `Retry-After: 1`; upstream 502/503/504 routed to a 503 JSON response |
   | Sensitive paths | Hidden files, backup/config/dump extensions and common unrelated exploit paths blocked |

   The API supplies normal CORS responses. Nginx has its own `$cors_origin` map for preflight and errors it generates;
   align that map with allowed frontends. Retain `Host`, real IP, forwarded address and scheme headers, and configure
   the API's trusted proxies/networks. Do not trust arbitrary forwarded headers from the public internet.

   HTTPS sets HSTS, frame denial, nosniff, XSS protection and referrer policy. CSP is **commented out**, not an
   active guarantee. Nginx header inheritance changes when locations add headers; verify each relevant route.
   Restrict `/hangfire` and application admin tools as appropriate in addition to their application authentication.

   ### Real-time hubs (`/hubs/`)

   `/hubs/notifications` has WebSocket upgrade headers using `$connection_upgrade`, buffering/cache off,
   3600-second read/send timeouts and `proxy_next_upstream off`. `limit_conn hub_conn 50` replaces the generic
   connection budget for this location. The `json_hubs` format logs `$uri` without the query string so
   `?access_token=` is not recorded; the infra configurations disable hub access logging.

   With multiple API instances use WebSockets and `skipNegotiation: true`, or explicitly add session affinity.
   The Redis backplane distributes sends; it does not provide Nginx affinity. See [real-time operations](../Modules/Notification-Realtime-and-Push.md#operations).

4. Review performance settings against request and upload limits.

   ### Performance tuning

   Global buffering uses a 128k client body buffer, a 50M request body limit, a 4k initial proxy buffer and
   `8 4k` proxy buffers; gzip is enabled at level 6. Upstream
   keepalive avoids opening a connection per request. Read/send/connect defaults are 60 seconds; the auth location
   uses 30 seconds and probes use five seconds. Long attachment operations can outlast these values; align ingress
   limits with `RequestTimeouts:LongRunningSeconds` and attachment size limits before serving large uploads.
   Do not assume that generic cache-zone examples enable API caching: the main route explicitly bypasses it.
   Any selective API caching must account for authentication, tenant scope and invalidation. Inspect static
   caching and body limits in the selected host or infra config rather than transferring defaults between them.

5. Install, validate and reload the reviewed host files:

   ```bash
   sudo cp deployment/nginx/nginx.conf /etc/nginx/nginx.conf
   sudo cp deployment/nginx/conf.d/app-production.conf /etc/nginx/sites-available/starterkit
   sudo ln -sf /etc/nginx/sites-available/starterkit /etc/nginx/sites-enabled/starterkit
   sudo rm -f /etc/nginx/sites-enabled/default
   sudo nginx -t
   sudo systemctl reload nginx
   sudo systemctl enable nginx
   ```

## Verify

```bash
curl -I https://api.example.com/health
curl -I http://api.example.com/health
sudo nginx -t
sudo certbot renew --dry-run
```

Test authenticated traffic, rejected tool access, WebSocket reconnects and a rate-limited API route separately.
`/health` cannot demonstrate rate limiting because it bypasses the limit. `/nginx_status` is restricted to loopback
in the HTTPS server; account for TLS/Host when inspecting it. A successful `nginx -t` checks syntax and referenced
files, not database readiness or external reachability.

### Monitoring

Host logs are `/var/log/nginx/starterkit-http-access.log`, `starterkit-http-error.log`,
`starterkit-https-access.log`, `starterkit-https-error.log` and `starterkit-hubs-access.log`. JSON request logs
include request/upstream timing; inspect slow requests, status distributions and limit errors. Keep query-string
logs protected. Use `sudo systemctl status nginx` and `sudo nginx -T` for service/loaded-config investigation;
review debug logging locally and restore normal verbosity after diagnosis.

## Pitfalls

### Troubleshooting

| Symptom | Check |
|---|---|
| 502/503 | API listener, readiness and migrator logs; upstream port/name and proxy error log |
| TLS errors | Domain, expiry, chain, referenced include files and renewal timer |
| 429 | Actual API/auth limit and traffic source; change the selected config, not unused environment variables |
| Tool 403 | Explicit allow-list plus application enablement/authentication |
| Socket drops | Upgrade headers, timeouts, Redis and session-affinity/client transport requirements |
| Slow responses | Upstream timing, host/container resource limits and backend traces before changing buffers |

`NGINX_CONFIG_FILE` and the old Makefile `nginx-*` shortcuts do not add an absent Compose service. The host
configuration does not substitute `.env.nginx` rate-limit variables. Start from the reviewed host files for
production; container config snippets with `api:80` are not valid host upstreams without matching networking.
